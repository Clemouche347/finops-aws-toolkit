# client-root — Terraform entry point

Terraform entry point for a FinOps engagement. Three independent roots, each with its own state.

## Getting started

```bash

SRC=~/projects/finops/finops-aws-toolkit/terraform/client-root
DST=~/projects/finops/finops-missions/clients/<client>

mkdir -p "$DST"/{terraform-iam,terraform-global,terraform-region}

cp "$SRC"/terraform-iam/*.example     "$DST"/terraform-iam/
cp "$SRC"/terraform-global/*.example  "$DST"/terraform-global/
cp "$SRC"/terraform-region/*.example  "$DST"/terraform-region/

find "$DST" -name '*.example' -exec bash -c 'mv "$0" "${0%.example}"' {} \;


```

```bash
# In each root: fill in terraform.tfvars, then:
terraform init
terraform plan
terraform apply
```

## Three Terraform roots

| Root | Provider region | Resources |
|---|---|---|
| `terraform-global/` | `us-east-1` (fixed) | cur-exports, athena-results-cur, finops-cur workgroup, CUR Glue table |
| `terraform-region/` | `var.infra_region` (tfvars) | compute-optimizer-results, s3-inventory, s3-logging, athena-results-s3, finops-s3 workgroup, S3 Glue tables, source bucket logging/inventory config, SSM parameter |
| `terraform-iam/` | `us-east-1` (fixed, IAM is global) | finops-auditor user, IAM policies |

## Recommended order of operations

1. **Manual prerequisites** (see section below) — complete before the first `apply`.
2. `terraform apply` in `terraform-global/` and `terraform-region/` — creates buckets, workgroups, SSM parameter, empty CUR table. `enable_s3_analysis = false` by default.
3. **Create the CUR export** in AWS Data Exports (manual). Wait for the first snapshot (~24 h).
4. **Populate `columns`** in `module.glue_cur_table` from the `create-table.sql` generated by AWS.
5. *(If S3 analysis)* Set `enable_s3_analysis = true`, fill in `s3_source_bucket_names` and `inventory_projection_start`, then `terraform apply` — also configures server access logging and S3 Inventory on the source buckets. Wait for the first inventory snapshot (~24–48 h).
6. *(If S3 analysis)* **Populate `inventory_columns`** in `module.glue_s3_tables` from the `fileSchema` in the `manifest.json`.

## Flag: enable_s3_analysis

This flag gates four resources that form a coherent set:

| Resource | Module | Condition |
|---|---|---|
| `s3-inventory` and `s3-logging` buckets | `audit_buckets_infra` | `create_analysis_group = enable_s3_analysis` |
| `finops-s3` workgroup | `athena_workgroups_s3` | `create_s3_workgroup = enable_s3_analysis` |
| `finops_s3` Glue tables | `glue_s3_tables` (for_each) | instantiated only if `enable_s3_analysis = true` |
| Server access logging + S3 Inventory on source buckets | `s3_source_config` (for_each) | instantiated only if `enable_s3_analysis = true` |

The `compute-optimizer-results` bucket is always created (independent of S3 analysis).

When `enable_s3_analysis = false`: S3 analysis modules create no resources. No S3 variables are required.

## Manual steps (outside Terraform)

These actions are not managed by this code and must be performed separately.

### Before the first apply
- **Enable IAM access to billing**: root action only — AWS Console → Account → IAM user and role access to Billing information.

### After the first apply
- **Create the CUR export** in AWS Console → Billing → Data Exports:
  - Export name: `finops_cur`
  - Format: Parquet
  - Granularity: Hourly
  - S3 prefix: `cur/`
  - Destination bucket: output `cur_exports_bucket_name` from module `audit_buckets_cur`
  - *(Optional)* Request a backfill of previous months via an AWS Support ticket.
- **Opt in to Compute Optimizer**: AWS Console → Compute Optimizer → Get started.
- **Opt in to Cost Optimization Hub**: AWS Console → Billing → Cost Optimization Hub → Get started.
- **Activate cost allocation tags**: AWS Console → Billing → Cost allocation tags → activate the relevant tags.

### Always
- **Populate CUR table `columns`** after the first snapshot:
  - Retrieve `s3://[cur-exports-bucket]/cur/finops_cur/metadata/BILLING_PERIOD=yyyy-MM/finops_cur-create-table.sql`
  - Extract the columns and populate the `columns` variable in `module.glue_cur_table`, then re-run `apply`.
  - Note: partition projection is NOT present in this SQL file — it is managed by the Terraform module.

### If enable_s3_analysis = true
- **Populate `inventory_columns`** after the first inventory snapshot:
  - Read the `fileSchema` from `s3://[s3-inventory-bucket]/[source-bucket]/inventory-finops/hive/dt=[YYYY-MM-DD-HH-mm]/manifest.json`
  - Populate the `inventory_columns` variable in `module.glue_s3_tables` and re-run `apply`.
- **Set `inventory_projection_start`**:
  - Read the date from the `hive/dt=` folder name or the `creationTimestamp` field in the `manifest.json`.
  - Expected format: `yyyy-MM-dd-HH-mm` (e.g. `2026-06-17-01-00`).
